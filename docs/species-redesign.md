# 동물 종·등급 중심 개편

도감은 동물 종마다 모든 모습을 묶어 표시한다. 보관함은 동물 종 선택과 등급 필터를 제공하고 기본 정렬도 종별로 묶는다. 기존 컬렉션 ID와 보유 수량, 과거 훈장·업적은 유지한다.

## 획득 경로

- 기존 다섯 뽑기의 풀을 유지한다. 아기 시리즈는 교배로만 획득한다. 노말·레어·에픽·유니크·레전더리·히든·이벤트는 표시·추첨·관리자 편집에서 각각 별도 등급으로 유지한다.
- `evolution_*` ID의 88종은 진화 전용이다. 일반 동물 12종과 고양이 품종 10종에 레어·에픽·유니크·레전더리 모습을 각각 추가했다. 원본 일러스트를 재사용하며 이름·ID·진화 표시·오라로 구분한다. 관리자에서 별도 일러스트를 업로드할 수 있다.
- 진화는 같은 동물 종을 유지한다. 원래 레어·에픽·유니크 동물도 다음 등급의 진화 전용 모습으로 진화한다. 걸음·코인 비용은 기존 값을 유지한다.
- 교배장·알 부화·합성·재활용은 기존 화면과 규칙으로 유지한다. 이 기능들은 기존 제작 풀을 사용하며 진화 전용 동물은 만들지 않는다. 기존 시작 동물 지급도 유지한다.

## 뽑기 기본값

기존 뽑기의 등급별 확률 합계를 유지한다. 먼저 등급을 추첨하고, 해당 뽑기에서 선택된 등급의 동물을 균등하게 추첨한다. 고양이는 레전더리 10종 0.9%, 히든 10종 0.1%로 각각 구분한다.

노말·프리미엄·가을·바다·고양이 뽑기의 기존 이름·포스터·가격·풀을 유지한다. 뽑기 종류와 동물 등급은 별개이다. 등급을 먼저 추첨하고 해당 뽑기 풀에서 같은 등급의 동물을 균등 추첨한다.

| 기존 뽑기 | 1회/10회 코인 |
|---|---|
| 노말 | 5/45 |
| 프리미엄 | 10/90 |
| 가을 | 8/72 |
| 바다 | 8/72 |
| 고양이 | 10/90 |

관리자는 등급별 확률 일곱 개를 편집한다. 합계 100%를 검증하며 아기·진화 전용 동물을 뽑기에 넣을 수 없다. 동물 추가·등급 편집 시 해당 뽑기의 기존 풀 안에서 다시 배분한다. 뽑기권 사용 조건은 기존처럼 1회 10코인 이하이다.

## 기존 서비스 적용 순서

1. `node scripts/generate-gacha.js`와 `node scripts/prepare-remote-gacha.cjs`로 기본 카탈로그·규칙을 생성한다.
2. 새 Firestore 규칙과 웹 빌드를 배포한다. 아직 실행 중인 이전 앱은 바뀐 진화·교배 경로를 사용할 수 없으므로 새 버전 안내가 필요하다.
3. 관리자 페이지의 **동물·등급 개편 초안 적용 → 변경 내용 검토 → 검토한 변경 게시**를 실행한다. 기존 원격 카탈로그를 자동으로 덮어쓰지 않는다. 원격에서 추가한 동물·이미지는 유지한다. 개편 버튼은 뽑기 가격·확률을 위 기본값으로 설정하므로 게시 전에 조정한다.
4. 모바일 앱 새 버전을 배포한다. 새 진화 대상이 없는 이전 원격 카탈로그에서는 새 진화 경로가 활성화되지 않는다.

## 지도

앱 WebView의 HTML 소스를 고정하고 캐시를 켰다. 웹 탭은 화면을 유지하고, iframe 준비 메시지를 놓쳐도 `onLoad`에서 브리지를 연결한다. 웹 마커는 썸네일을 CSS로 얼굴 크롭하여 이미지 다운로드 후 canvas PNG 변환을 기다리지 않는다.

지도 중심·확대는 세션 저장소로 복원한다. 내 위치는 권한이 있을 때만 최근 10분 이내 캐시를 먼저 표시하고 새 위치로 갱신한다. 표시용 캐시를 다른 이용자에게 공유하지 않는다. 타인의 위치는 기존 실시간 구독과 공개·친구 권한 검사를 유지한다. 지도 타일은 브라우저/WebView HTTP 캐시를 사용하며 오프라인 지도 다운로드는 추가하지 않았다.

웹 위치는 HTTPS 또는 localhost에서 브라우저 위치 권한이 필요하다. 권한 거부·위치 조회 실패 시 허용 안내를 표시한다. 기기에 따라 실제 위치 정확도는 달라진다.
